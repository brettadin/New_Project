# 6.9 — Contextual Guidance and Workflow Assistance

## Purpose

The application should help users understand and navigate scientific work while they are actively using its tools, workspaces and research environments.

This section focuses on assistance that responds to the user's current scientific activity, data, tools and workflows.

It complements Section 6.6.7 (Help, Tooltips and Contextual Assistance), with the following distinction:

- **Section 6.6:** General usability, onboarding, help and access to documentation.
- **Section 6.9:** Assistance that responds to current scientific activities, datasets, tools and workflows.

The objective is to make complex scientific operations easier to understand without constantly interrupting users, imposing rigid procedures or taking control away from them.

---

## 6.9.1 — Context-Aware Guidance Principles

The application should provide a combination of on-demand assistance, contextual guidance and occasional proactive suggestions.

Users should be able to access help whenever needed while also receiving relevant guidance during scientific activities.

### Core Requirements

- **On-demand guidance:** Allow users to request explanations, instructions and scientific information whenever needed.
- **Contextual assistance:** Provide relevant guidance based on the current workspace, tool, dataset or scientific activity.
- **Proactive suggestions:** Offer potentially useful next steps, resources or capabilities when there is a clear reason.
- Allow users to access relevant documentation and educational resources without leaving their current workflow.
- Explain unfamiliar terminology, scientific methods and application operations.
- Provide assistance when users encounter errors, compatibility issues or unfamiliar operations.
- Allow users to dismiss suggestions and continue working without following them.
- Avoid unnecessary prompts, repetitive explanations and workflow interruptions.
- Distinguish informational guidance, optional recommendations and genuinely necessary actions.

### Future Possibilities

- Guidance that adapts to user experience and activity.
- More advanced context-sensitive recommendations.
- Connections between scientific knowledge, educational material and application functionality.
- Personalized assistance based on previous research activities.

### Important Considerations

- Users should be able to adjust how proactive the application is.
- Guidance should become less intrusive when users are already familiar with particular operations.
- Suggestions must have a reasonable scientific or practical justification.
- The application must not assume that its suggested workflow is the only appropriate approach.
- Scientific recommendations must remain transparent about their assumptions, limitations and suitability.

**Design Principle:** Combine accessible help, relevant contextual explanations and useful proactive suggestions while allowing users to control how much assistance they receive.

---

## 6.9.2 — Tool and Feature Explanations

The application should provide explanations for its scientific tools and capabilities at different levels of detail, allowing users to understand both how functionality works and the scientific principles behind it.

### Core Requirements

Provide three levels of explanation:

#### 1. Quick Explanation

- What the tool does.
- Its primary purpose.
- What type of scientific problem it helps address.

#### 2. Practical Guidance

- How to use the tool.
- Required input data and prerequisites.
- What its controls and parameters mean.
- How to interpret its outputs.
- Common mistakes and potential problems.

#### 3. Scientific Explanation

- Underlying scientific principles.
- Relevant physics, chemistry and mathematics.
- Equations and methodology.
- Assumptions and limitations.
- Appropriate applications and circumstances where the method may be unsuitable.
- Relevant scientific references and further reading.

### Additional Requirements

- Make explanations accessible directly from relevant tools and features.
- Allow users to move between explanation levels without losing their current workflow.
- Connect explanations to relevant educational resources in Section 7.
- Keep explanations consistent with the actual implementation and scientific capabilities.
- Update explanations when functionality or scientific methods change.

### Future Possibilities

- More interactive explanations.
- Examples using real or clearly identified simulated datasets.
- Context-sensitive explanations based on selected parameters or operations.
- Links between related tools, methods and scientific concepts.

### Important Considerations

- Explanations must distinguish established scientific principles from assumptions, approximations and experimental methods.
- Scientific explanations should not be oversimplified to the point of becoming inaccurate.
- Documentation must reflect what the tool actually does, not merely what it is intended to do.

**Design Principle:** Every scientific tool should be understandable at a basic level while providing access to the deeper scientific knowledge required for rigorous use.

## 6.9.3 — Scientific Workflow Guidance

The application should provide guidance for broader scientific workflows, helping users understand how individual tools and analytical stages relate to one another without imposing rigid procedures.

For example, a spectroscopy investigation might involve:

1. Importing and inspecting observations.
2. Checking metadata and data quality.
3. Determining appropriate calibration and preprocessing.
4. Identifying spectral features.
5. Comparing observations with reference databases.
6. Performing atmospheric analysis or modelling.
7. Evaluating uncertainty and alternative interpretations.
8. Recording and exporting results.

The application should help users understand how these stages relate, what prerequisites are necessary and what options are available.

### Core Requirements

- Provide guidance for common scientific workflows across relevant disciplines.
- Explain the purpose and relationship of individual workflow stages.
- Identify required inputs, prerequisites and dependencies.
- Explain what outputs are produced and how they can be used in subsequent stages.
- Identify potential compatibility issues and missing requirements.
- Suggest appropriate next steps based on the current investigation.
- Allow users to modify, skip, reorder or add workflow stages where scientifically appropriate.
- Support both guided workflows and independent use of individual tools.
- Preserve workflow configurations and analytical history where required for reproducibility.

### Future Possibilities

- More extensive guided workflow libraries.
- User-created and reusable workflow templates.
- Context-sensitive workflow recommendations.
- More advanced workflow adaptation based on datasets and research objectives.
- Connections to community-created workflows and educational exercises.

### Important Considerations

- Workflows should be starting points, not mandatory procedures.
- Different datasets, instruments and research objectives may require different approaches.
- The application should explain when modifying a workflow could affect scientific validity.
- Required scientific dependencies and compatibility checks must not be bypassed simply because a user changes the sequence.
- Workflow guidance should complement Sections 3, 5 and 6.3 rather than duplicate their underlying functionality.

**Design Principle:** Help users understand and navigate scientific workflows while preserving flexibility, independent exploration and the ability to adapt procedures to individual investigations.

## 6.9.4 — Contextual Recommendations and Suggestions

The application should provide optional recommendations across scientific workspaces and research activities, identifying potentially useful tools, datasets, resources, analyses and research directions based on the user's current work.

Examples include:

- Suggesting relevant reference databases when examining a spectrum.
- Identifying potentially useful observations for an astronomical object.
- Recommending comparisons with related datasets.
- Highlighting analytical methods that may help investigate a particular feature.
- Identifying potentially relevant educational material or scientific literature.

### Core Requirements

- Recommend relevant scientific tools and capabilities.
- Identify potentially useful datasets, observations and external resources.
- Suggest relevant scientific literature and educational material.
- Recommend analytical methods and workflows where appropriate.
- Identify opportunities for comparisons between objects, datasets or scientific disciplines.
- Suggest possible avenues for further investigation.
- Identify potentially useful capabilities that users may not know exist.
- Make recommendations relevant to the current workspace, project, dataset or research activity.
- Allow users to dismiss, ignore or act on recommendations independently.

For each recommendation, communicate:

- Why it is being suggested.
- Its potential scientific or practical value.
- Relevant prerequisites and compatibility requirements.
- Known limitations or uncertainties.
- Whether it is based on scientific relevance, data compatibility or general convenience.

### Future Possibilities

- Recommendations informed by previous research activities.
- More advanced cross-disciplinary discovery.
- Identification of emerging research opportunities.
- Personalized recommendations based on user preferences and experience.
- Community-informed recommendations, with popularity clearly distinguished from scientific credibility.

### Important Considerations

- Recommendations must remain optional.
- Do not automatically retrieve substantial datasets, execute analyses or modify research configurations.
- Do not present recommendations as scientifically necessary unless they genuinely are.
- Avoid repetitive, irrelevant or excessive suggestions.
- Preserve user control over research direction.
- Recommendations involving scientific methods must communicate suitability, assumptions and limitations.

**Design Principle:** Help users discover useful scientific capabilities and research opportunities without directing or restricting their investigations.

## 6.9.5 — Workflow Progress and Next-Step Guidance

The application should provide an optional overview of progress within scientific investigations and workflows, helping users understand completed activities, outstanding work and potential next steps.

For example, during an atmospheric characterization investigation, the application might show:

- Data successfully imported.
- Metadata and quality checks completed.
- Calibration still required.
- Spectral analysis in progress.
- Reference comparisons available.
- Uncertainty assessment outstanding.

It could also identify incomplete steps, dependencies and potential issues.

### Core Requirements

- Provide an optional overview of investigation and workflow progress.
- Show completed, ongoing, pending and outstanding stages where applicable.
- Identify incomplete steps and outstanding prerequisites.
- Highlight dependencies between workflow stages.
- Identify potential issues that may prevent subsequent operations.
- Suggest possible next steps based on the current investigation.
- Allow users to access more detailed progress information within individual workflows.
- Allow users to dismiss, hide or customize progress overviews.
- Preserve progress information when investigations are saved, reopened or continued.

### Future Possibilities

- More advanced progress visualization.
- Customizable progress indicators and workflow summaries.
- Progress comparisons between alternative workflow branches.
- More detailed tracking across multiple investigations.
- Context-sensitive suggestions based on incomplete activities.

### Important Considerations

- Progress tracking must remain optional and informative rather than prescriptive.
- Not every investigation requires a predefined sequence or completion checklist.
- Users must be able to leave stages incomplete, skip unnecessary steps or pursue alternative approaches.
- Completing a workflow stage does not imply that its scientific results have been validated.
- Coordinate with existing project and analysis status systems to avoid duplicate tracking.

**Design Principle:** Give users a clear overview of their research progress without imposing artificial completion requirements or restricting their investigative approach.

---

## 6.9.6 — Guidance Customization and User Control

The application should allow users to control how contextual guidance and workflow assistance are presented, beginning with a simple set of preferences and expanding customization as the application develops.

### Core Requirements

- Provide basic controls for enabling or disabling proactive suggestions.
- Allow users to access guidance manually regardless of their proactive assistance settings.
- Provide a basic preference for the level of explanation presented by default.
- Allow users to enable or disable optional workflow progress overviews.
- Avoid excessive settings and configuration complexity initially.
- Ensure guidance preferences persist between sessions.
- Allow global preferences to be adjusted as the application develops.

### Future Possibilities

- More detailed customization of contextual assistance.
- Workspace-specific and project-specific guidance preferences.
- Different guidance levels for individual tools and activities.
- Personalized assistance based on experience and previous activity.
- Customizable recommendation frequency and presentation.
- Importing and exporting guidance preferences.

### Important Considerations

- Initial settings should be straightforward and understandable.
- Customization should expand in response to actual user needs.
- Disabling proactive guidance must not remove access to documentation, explanations or educational resources.
- Guidance settings should not interfere with essential scientific warnings or critical error notifications.
- Coordinate with Section 6.8 so guidance preferences integrate with the broader application preference system.

**Design Principle:** Provide useful assistance by default while allowing users to determine how much guidance they receive, with customization expanding gradually rather than overwhelming the initial experience.

## Section 6.9 — General Principles

The overall contextual guidance system should follow these principles:

1. **Contextual relevance:** Assistance should respond to the user's current scientific activity rather than provide generic or unrelated suggestions.
2. **User control:** Users decide when to follow recommendations and how much assistance they receive.
3. **Scientific accuracy:** Explanations and recommendations must be scientifically credible, transparent and consistent with actual functionality.
4. **Flexibility:** Guided workflows should accommodate different research objectives, datasets and methodologies.
5. **Accessibility:** Beginners should be able to access understandable explanations without limiting advanced users.
6. **Integration:** Guidance should connect with scientific documentation, educational resources, workflow systems and existing application capabilities.
7. **Non-intrusiveness:** Assistance should support research rather than interrupt or dictate it.
8. **Adaptability:** The system should be capable of expanding as scientific capabilities and user requirements develop.

### Initial Implementation Priorities

The initial application should establish:

- Contextual and on-demand guidance.
- Three levels of tool and feature explanations.
- Flexible guidance for common scientific workflows.
- Optional, explainable recommendations.
- Optional workflow progress overviews.
- Basic guidance preferences and user controls.
- Connections to the educational and documentation systems.

More advanced personalization, recommendation systems, workflow libraries and customization can be investigated and introduced later.

### General Principle

Contextual guidance should make the application easier to understand and more capable of supporting scientific research without restricting independent investigation. It should help users understand their tools, workflows and research opportunities while preserving scientific rigor, flexibility and user control.

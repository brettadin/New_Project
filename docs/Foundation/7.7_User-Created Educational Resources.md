# 7.7 — User-Created Educational Resources

## 7.7.1 Personal Educational Notes and Reference Material

Users should be able to create and maintain their own educational notes and reference material within the application.

This should support:

- Personal notes about astronomical concepts and scientific principles.
- Explanations of mathematical, physical and chemical relationships.
- Definitions of scientific terminology.
- Summaries of educational material and scientific publications.
- Worked examples and calculations.
- Notes about scientific methods, equations and analytical techniques.
- Questions, ideas and topics requiring further investigation.
- Personal interpretations and observations made during learning.

Users should be able to create, edit, organize and revisit these materials independently of formal research projects.

Educational notes should be distinguishable from official application documentation, published scientific literature and established scientific reference material.

Where notes are based on external sources, users should be able to associate relevant references and citations with them.

Personal notes should remain under the user's control and should not automatically become public or be incorporated into official application educational content.

## 7.7.2 User-Created Tutorials and Learning Material

Users should be able to develop their own educational material beyond simple notes.

Potential resource types include:

- Tutorials explaining scientific concepts.
- Step-by-step explanations of mathematical methods.
- Guides to astronomical research techniques.
- Explanations of scientific equations and calculations.
- Educational walkthroughs of application tools.
- Subject-specific reference guides.
- Introductory explanations for more advanced topics.
- Structured lessons covering particular scientific subjects.

Users should be able to organize material into sections and subsections, allowing more substantial educational resources to be developed.

Where appropriate, resources should support text, mathematical expressions, scientific equations, images, diagrams, graphs, tables, references and links to other educational material.

The system should accommodate both short explanations and more comprehensive educational documents.

Users should not be restricted to a single predefined educational format.

## 7.7.3 Custom Learning Paths and Educational Collections

Users should be able to organize educational resources into personal collections and, where appropriate, custom learning paths.

This could include:

- Collections of related educational notes.
- Subject-specific reference libraries.
- Personally organized courses.
- Learning paths covering multiple scientific subjects.
- Collections of mathematical explanations and worked examples.
- Reading lists and collections of scientific publications.
- Groups of tutorials associated with particular application tools or research activities.

Users should be able to organize resources according to their own learning objectives rather than being restricted to the application's predefined educational structure.

Custom learning paths should allow users to arrange topics in a preferred order, establish relationships between subjects and identify prerequisite knowledge where relevant.

These personal structures should complement the official educational library and courses established in Sections 7.1 and 7.2 rather than replacing them.

## 7.7.4 Educational Resources Using Astronomical Data

Users should be able to create educational material using astronomical observations, datasets and scientific tools available within the application.

Examples include:

- Tutorials demonstrating spectral analysis using real observations.
- Explanations of molecular identification using reference spectra.
- Worked examples involving planetary or stellar characterization.
- Exercises demonstrating photometric measurements.
- Educational investigations using exoplanet transit observations.
- Comparisons between Solar System and exoplanetary observations.
- Demonstrations of atmospheric modelling and parameter exploration.
- Explanations of data processing and scientific interpretation.
- Tutorials showing how different analytical methods affect results.

Where practical, educational resources should be able to reference existing datasets, visualizations, analyses and application configurations.

Users should be able to demonstrate scientific methods using actual application functionality rather than relying exclusively on static explanations.

The system should preserve relationships between educational resources and the datasets or tools they use.

Where educational material relies on simulated, synthetic or illustrative data, this must remain clearly identified in accordance with the scientific integrity requirements in Section 5.1.

Educational examples must not be presented as genuine astronomical observations when they are simulated or fabricated.

## 7.7.5 Reusable Educational Demonstrations and Examples

Users should be able to create or preserve educational examples that can be revisited and reused.

Potential examples include:

- Saved mathematical calculations.
- Parameter configurations for interactive demonstrations.
- Example spectra and associated interpretations.
- Example light curves and photometric analyses.
- Model configurations illustrating particular scientific relationships.
- Worked analytical procedures.
- Demonstrations of alternative scientific interpretations.
- Example datasets with accompanying educational explanations.

Where practical, these resources should preserve the relevant configuration, inputs, parameters and outputs required to reproduce the demonstration.

Users should be able to revisit and modify examples without unintentionally altering the original resource.

The system should distinguish between educational examples, actual research analyses and validated scientific results.

Where an educational example is based on a real research workflow, its relationship to the original scientific method and data should remain traceable.

## 7.7.6 Connections to Existing Educational and Scientific Resources

User-created educational material should be able to connect to the wider application.

Where relevant, users should be able to link their resources to:

- Topics in the scientific knowledge library.
- Official educational courses and learning paths.
- Interactive demonstrations and exercises.
- Scientific equations and mathematical explanations.
- Application tools and workflows.
- Astronomical objects and planetary systems.
- Datasets and observations.
- Scientific publications and references.
- Research projects and analyses.
- Other user-created educational resources.

These connections should make it easier to navigate between personal material and established scientific information.

For example, a user creating a tutorial about molecular spectroscopy could link relevant equations, molecular reference data, spectral analysis tools, educational demonstrations and scientific publications.

The application should preserve these relationships when educational resources are reorganized or moved.

Links to external resources should retain their source information and should be identifiable if they become unavailable.

## 7.7.7 Resource Organization and Management

Users should be able to organize and maintain their educational material over time.

Potential functionality includes:

- Creating folders, categories and collections.
- Applying tags and keywords.
- Searching personal educational resources.
- Editing and reorganizing material.
- Duplicating resources for separate purposes.
- Identifying related resources.
- Marking material as incomplete, in progress or complete.
- Archiving older resources without necessarily deleting them.
- Identifying resources requiring revision.
- Maintaining links between related educational material.

Organization should remain flexible enough to accommodate different learning approaches and subject areas.

The system should avoid imposing a rigid hierarchy on personal educational material.

Users should be able to organize resources by subject, learning objective, scientific discipline, application functionality or another personally meaningful structure.

## 7.7.8 Version History and Educational Resource Maintenance

Users should be able to revise their educational material without unnecessarily losing earlier work.

Where appropriate, the system should preserve:

- Previous versions of educational resources.
- Significant changes and revisions.
- Creation and modification dates.
- Associated references and source information.
- Relationships with other educational resources.
- Relevant datasets, examples and configurations.

Users should be able to revisit earlier versions and restore previous content where practical.

This is particularly important for educational material that develops alongside the user's scientific understanding.

Where a user discovers that an earlier explanation contains an error or outdated information, they should be able to revise it while retaining an appropriate history of the changes.

The application should distinguish between changes to personal educational material and changes to official application documentation or established scientific reference material.

Where an educational resource depends on external publications, databases or software, significant changes to those dependencies should be identifiable where technically practical.

## 7.7.9 Distinction Between Personal, Community and Official Content

The application should clearly distinguish between different origins and levels of authority for educational resources.

These should include:

**Official application educational content**
- Material developed and maintained as part of the application's educational system.
- Subject to the application's educational quality and scientific validation requirements.
- Clearly identifiable as official application material.

**Personal user-created content**
- Notes, tutorials, explanations, examples and collections created by individual users.
- Private by default.
- Controlled and maintained by their creator.
- Not automatically considered scientifically reviewed or validated.

**Community-created educational content**
- Resources intentionally shared with other users.
- Associated with their creator and relevant source information.
- Subject to any applicable community review or feedback processes.
- Not automatically treated as official or scientifically validated.

These distinctions should remain visible when resources are accessed, referenced, exported or shared.

The application should not imply that user-created content has been scientifically reviewed simply because it is stored within the platform.

Further requirements for sharing and community contributions are addressed in Section 7.8.

## 7.7.10 Export and Portability of Educational Resources

Users should be able to export and preserve their educational material outside the application.

Where practical, this should include:

- Educational notes and documents.
- Tutorials and structured learning material.
- Personal learning paths and collections.
- Mathematical expressions and equations.
- Associated references and citations.
- Relevant images, diagrams and visualizations.
- Linked datasets and example configurations where permitted.
- Resource metadata and organization.

Export should preserve as much of the original structure and formatting as possible.

Common document formats should be investigated, including Markdown, PDF and other appropriate formats.

Where an exported resource depends on application-specific functionality, the application should identify those dependencies and explain what may not be preserved outside the platform.

Educational resources should not become unnecessarily locked into the application.

## Future Possibilities

The following capabilities may be considered as the educational system develops:

- More advanced personal course and tutorial creation.
- Custom interactive educational demonstrations.
- User-created exercises and assessments.
- Educational resource templates.
- More extensive integration with application tools and workflows.
- User-defined educational modules and structured programmes.
- Personal learning progress and knowledge tracking.
- AI-assisted educational resource creation and revision.
- Conversion of personal notes into structured educational material.
- Importing educational resources from external formats.
- Collaborative educational resource development.
- Sharing and publishing personal educational material.
- Community-created tutorials, demonstrations and learning paths.
- Community review and improvement of educational resources.
- Importing and adapting educational resources created by other users.

These capabilities should be evaluated according to educational value, scientific accuracy, usability, technical feasibility and their relationship to the wider educational system.

## Initial Implementation Scope

Initial user-created educational functionality should prioritize:

- Creating and editing personal educational notes.
- Organizing notes and reference material.
- Supporting mathematical expressions, equations and scientific formatting.
- Adding references and links to existing educational material.
- Associating notes with relevant scientific topics and application areas.
- Saving personal educational collections.
- Preserving user-created material between sessions.
- Basic resource searching and organization.
- Exporting personal educational material where practical.

More advanced tutorial creation, interactive educational content, custom learning paths and community sharing can be introduced later.

The initial implementation should establish a reliable foundation for personal educational material without requiring a complete user-generated educational publishing system.

## Implementation Considerations

- Personal educational resources should be private by default.
- Users should retain control over their own material.
- User-created content must remain distinguishable from official application content.
- Educational resources should not automatically be considered scientifically verified.
- References and source information should be preserved wherever possible.
- Educational examples must clearly distinguish genuine observations from synthetic, simulated or illustrative material.
- Links to application tools and scientific resources should remain connected to their actual functionality.
- Changes to educational resources should not silently alter associated research data or scientific records.
- Resource organization should remain flexible and adaptable.
- Export and portability should be considered from the beginning.
- Community sharing and permissions should align with the requirements established in Section 8.
- Scientific accuracy and educational quality should align with the requirements established in Sections 5 and 7.9.

## General Principle

The application should allow users to develop and maintain their own educational resources as part of their wider scientific learning environment.

Personal notes, explanations, tutorials, worked examples and learning collections should be integrated with the application's scientific knowledge, educational material, datasets and analytical tools.

Users should be able to build upon their understanding over time, organize information according to their own needs and retain ownership and control of their personal material.

The objective is to support independent learning and knowledge development without restricting users to predefined educational content or requiring them to share their work.
